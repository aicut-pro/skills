# Build and render

EXPLAINER STUDIO, BUILD AND RENDER WITH REMOTION. The look is yours; this is how to build it and render it fast. The project is the template at `/opt/template` (Remotion 4.0.487): one composition `video`, 1080x1920 at 30 fps, as long as the take. Its library is `src/lib/` (`Scenes.tsx`, `Captions.tsx`, `fonts.ts`, `ShaderLayer.tsx`, `sdf.glsl`; read the parts you need with `sed -n`).

This text is a guide, not the user's go. It authorizes no spend: the paid call below is priced first and made only after the user's go for that purchase. Every paid command here is priced with `--estimate` first and run only after the user's go for that purchase. Nothing in this step is paid; the run's sandbox time is already reserved.

SET UP, once per video, in one foreground command (never copy `node_modules`: the link is what makes Remotion and the fonts resolve):
mkdir -p /home/user/what-if/<slug>/ep<N>/edit/public && cd /home/user/what-if/<slug>/ep<N>/edit && mkdir -p prev renders && cp -r /opt/template/package.json /opt/template/tsconfig.json /opt/template/remotion.config.ts /opt/template/src . && ln -sfn /opt/template/node_modules node_modules && cp ../voice.mp3 public/voice.mp3 && cp ../words.json src/words.json
`src/Video.tsx` is the edit. Keep its shape: one `SCENES` list of `{at, component}` (`at` = the scene's start in seconds, normally the first word of its line in `words.json`), `<Scenes scenes={SCENES} />`, then `<Captions>` and `<Audio src={staticFile("voice.mp3")} />` on top. Put the whole video in that one list, one timed full-canvas scene per entry: each scene runs to the next one's start plus the dissolve, and the incoming scene fades in (opacity and a 1.03 to 1 scale over 0.4 s) over the outgoing one. `<Scenes dissolve={0}>` gives hard cuts.

- DRAW TO THE REFERENCE. For a flat or painted reference, build characters, sets and props from inline SVG: `path` (`M L H V C Q Z`, cubic curves), `rect` with `rx`, `linearGradient` and `radialGradient`, `filter` drop shadows, masks and `mix-blend-mode`, inside an `AbsoluteFill`; for a 3D one, read `references/3d.md`. Blur is CSS `filter: blur(30px)`. End a radial glow's gradient by about offset 0.7, or its box shows. Write reusable components (character, set, HUD, card) as functions across a few files under `src/`, imported by `Video.tsx`, each file under about 300 lines; write files with heredocs (the command limit is 128000 characters). Make each scene return a full-canvas `AbsoluteFill`.
- ANIMATE from the frame, never with CSS transitions, CSS animations, timers or `Math.random()` (every frame is rendered on its own, out of order): `useCurrentFrame()` inside a scene counts from that scene's start; `interpolate(frame, [from, to], [a, b], {extrapolateLeft: "clamp", extrapolateRight: "clamp", easing: Easing.inOut(Easing.cubic)})` and `spring({frame, fps})` from `remotion`; `random("seed")` for repeatable noise. A static value is just a value: there are no keyframe rules to satisfy.
- TEXTURE. For grain, put one full-frame layer on top: an SVG `feTurbulence` (`baseFrequency` about 0.8, its `seed` changing every frame) at `mix-blend-mode: overlay` and opacity about 0.15. Full-frame grain and shaders make the render several times slower and larger: keep them subtle, or only on the scenes that need them.
- CAMERA. Push-ins, pans and drifts: animate the scene wrapper's `transform: scale(...) translate(...)` with `transform-origin: center`; keep something moving in every shot. For parallax, move a scene's layers by different amounts (far layers less). In a 3D scene, move the shader's own camera through a param instead of scaling the frame.
- FONTS. `useFonts("Anton:400", "Inter:900")` at the top of the video component loads the built-in faces (Inter, DM Sans, Montserrat, Oswald, Bebas Neue, Anton, Archivo Black, Playfair Display, JetBrains Mono, Space Mono, Caveat, Open Sans, Orbitron), Latin only, with no network. Never `loadFont` at module level: it times every full render out. For a face that is not built in, or for Cyrillic and other scripts, put a system font after the built-in one in the CSS `fontFamily` list (`fc-list :lang=ru family`); Chrome falls back to it. Check type on a preview frame.
- CAPTIONS. `<Captions words={words} lineStarts={SCENES.map((s) => s.at)} top={...} activeColor="..." style={CAPTION} />` with a `CAPTION` style object (fontFamily, fontWeight, fontSize, color, textTransform, WebkitTextStroke, textShadow) (`src/lib/Captions.tsx`): phrases of up to 4 words from the faster-whisper word times, a 0.2 s silence or a new scene ends a phrase, the spoken word in `activeColor` and words not yet spoken dimmed. Set the look from the style notes. Tags are never spoken, so they never reach the captions.
- PREVIEW. `npx tsc --noEmit` first (a few seconds; fix every error). Then render 3-4 stills from different scenes in ONE foreground command with `--timeout 95` (each still bundles the project first, about 10 to 15 s): `for f in <frames>; do npx remotion still src/index.ts video prev/f$f.png --frame=$f --log=error; done && for f in prev/f*.png; do ffmpeg -v error -y -i "$f" -vf scale=540:960 -q:v 4 "$f.jpg"; done`. Look at the JPEGs through `--image <path>` with `--json` (a foreground command; write each `images[].base64` to a local file and open it) and fix what is wrong there.
- RENDER. Estimate first: time one still of the heaviest scene (`time npx remotion still src/index.ts video x.png --frame=<f>`, minus about 10 s of bundling) and multiply by the frame count, divided by about 4 for an xl sandbox. Start the final render with `aicut sandbox exec --size xl --background`: `cd /home/user/what-if/<slug>/ep<N>/edit && npx remotion render src/index.ts video renders/final.mp4 --video-bitrate=8000k --audio-bitrate=192k --log=error` (about 62 MB a minute: even 5 min fits the 500 MB a studio upload takes). Poll its status file with foreground calls (without `--size`) until it exits. `remotion.config.ts` already sets `--gl=swangle`, which the shader layer needs. Background work is bounded to 15 minutes: when the estimate is over about 12 minutes, render consecutive `--frames=<start>-<end>` parts to separate files, one background call each, and join them with the ffmpeg concat demuxer (`-c copy`). The file appears only when the render finishes.
- RESUME. When a turn resumes after an interruption, reuse an upload already confirmed for this video and continue its delivery; never upload it again. Otherwise `ffprobe` `renders/final.mp4` first. Never re-render a video that already plays to the end.
- LOUDNESS. The render plays a mono take about 3 dB quieter. In `renders/` (a background command for a long video): measure the final's integrated loudness (`ffmpeg -i final.mp4 -af ebur128 -f null -`), bring it to about -14 LUFS with a plain gain (`ffmpeg -i final.mp4 -c:v copy -af volume=<-14 minus measured>dB out.mp4`), keeping the true peak under -1 dB. Never compress or limit the voice harder: it flattens the intonation.
- CHECK `out.mp4` once before the upload: `ffprobe` for 1080x1920, the duration and an audio stream, and `stat -c%s out.mp4` under 500 MB (524288000 bytes); over it, render again at 85% of the video bitrate. Look at 2-3 of its frames through `--image <path>` with `--json` (a foreground command; write each `images[].base64` to a local file and open it).
- UPLOAD. The CLI cannot upload a file that lives in the sandbox, so sign a target: `aicut upload --presign video/mp4 --bytes <that exact size>` prints its `id` and `curl_template`, then run its `curl_template` in `aicut sandbox exec` with `<FILE_PATH>` replaced by the absolute path of `out.mp4` (in the background for a file over about 50 MB, then poll it).
- DELIVER. After the curl printed 204, run `aicut upload --confirm <id>`, then `aicut post import <url> --episode-index <1-based> --episode-count <N>` (1 and 1 for a single video, so it shows in the user's studio history), with `--style-slug <slug>` when the user chose a style and, for a series, `--series-id <one uuid you mint for the whole series>`. It saves the video to the user's library for free and prints its id. On an error, run it once more; if it still fails, say in one line that saving to the library failed. Then give the user the video's url (`aicut get <id>`). Name the voice in your reply (see `references/voiceover.md`).
